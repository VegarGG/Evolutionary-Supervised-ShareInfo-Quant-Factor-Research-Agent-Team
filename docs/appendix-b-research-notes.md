## B.1 MCP and Claude agent tooling (historical client comparison)

The product now uses standard MCP with Codex/generic-client acceptance; the Claude-specific subsections below are background only.

### Protocol state

- **Current revision 2026-07-28** (final July 28, 2026; release candidate May 21, 2026), superseding 2025-11-25 and 2025-06-18. Formal lifecycle policy of Active → Deprecated → Removed with a twelve-month minimum window. [Release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/) · [changelog](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx) · [release-candidate post](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/).
- **2025-06-18** added structured tool output (`outputSchema`, `structuredContent`), `resource_link` content in tool results, elicitation, servers classified as OAuth resource servers with protected-resource metadata, required RFC 8707 resource indicators, the protocol-version header, and removed JSON-RPC batching. [changelog](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-06-18/changelog.mdx)
- **2025-11-25** added experimental Tasks, URL-mode elicitation, client-id metadata documents, incremental scope consent, sampling with tools, icons, tool-naming guidance, and JSON Schema 2020-12 as default. [changelog](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/changelog.mdx)
- **2026-07-28 "stateless core":** the `initialize` handshake and session identifier are removed; every request carries protocol version and client capabilities in metadata; servers must implement `server/discover`; multi-round-trip requests return `input_required` with opaque state; `resultType` is required on all results; streamable-HTTP posts carry method and name headers; list results carry a time-to-live and cache scope; the GET stream, resource subscriptions, SSE resumability, ping and log-level setting are removed; roots, sampling, logging, the legacy HTTP+SSE transport and dynamic client registration are deprecated. Progress notifications ride the originating request's stream, and over HTTP **closing the response stream is the cancellation signal**. Servers should return tools in deterministic order for prompt-cache hits. [transport](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/streamable-http.mdx) · [cancellation](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/patterns/cancellation.mdx) · [versioning](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/versioning.mdx)
- **Tasks** moved from the core to the `io.modelcontextprotocol/tasks` extension (SEP-2663, status Final, created April 27, 2026). The client declares the extension per request; the server decides per request whether to answer a tool call with a task (states working, input_required, completed, failed, cancelled); `tasks/get` returns the result; cancellation is cooperative; a server must not return a task to a client that did not declare support; task ids are bearer-token-like and must be unguessable. Only `tools/call` is task-augmentable. [SEP-2663](https://tasks.extensions.modelcontextprotocol.io/seps/2663-tasks-extension) · [extension spec](https://tasks.extensions.modelcontextprotocol.io/specification/draft/tasks)
- **Authorization:** OAuth 2.1; the server is a resource server and must serve RFC 9728 protected-resource metadata; clients must send RFC 8707 resource indicators; client-id metadata documents are recommended and dynamic client registration deprecated; servers must validate audience and reject token passthrough; insufficient scope yields a 403 with the required scope for step-up. [authorization](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/authorization/index.mdx)
- **Tools and annotations:** `readOnlyHint` defaults false, `destructiveHint` true, `idempotentHint` false, `openWorldHint` true; hints are not guaranteed faithful and clients treat them as untrusted unless the server is trusted. If `outputSchema` is present, `structuredContent` must conform and should be mirrored as text. Tool names are 1–128 characters from a restricted alphabet. The spec itself sets no tool-count limit and gives no description-writing guidance; that guidance comes from Anthropic (below) and from Claude Code's truncation limits. [tools](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx) · [schema](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/schema/2026-07-28/schema.ts)

### Claude Code and Claude Desktop as clients

- Configuration: `claude mcp add --transport http <name> <url> --header ...` with local, project or user scope; project `.mcp.json` with environment-variable expansion; OAuth via `/mcp` or `claude mcp login`. [MCP docs](https://code.claude.com/docs/en/mcp)

[issue 102347](https://github.com/anthropics/claude-code/issues/102347)

Tool search is on by default with no fixed per-server cap; descriptions are truncated at 4,096 characters (16,384 when deferred); invalid schemas and names over 128 characters are excluded; resources are addressable as `@server:scheme://path`. [MCP docs](https://code.claude.com/docs/en/mcp)

### Distilled rules used in the plan

Serve both protocol eras from one endpoint; every tool returns in well under two minutes with submit-then-poll for long work; idempotency keys and honest annotations; small results with resource links; output schemas mirrored into text; OAuth as a resource server with research and evaluation scopes when multi-user; descriptions with the essential text first; a stateless front door over a durable job store; the evaluator never callable by research tools.

### Artifact conventions worth borrowing

- Qlib expression language: element-wise, rolling and pair operators over `$field` series; cross-sectional normalization is a processor step, not an operator; Alpha158 and Alpha360 feature sets. AlphaBench standardizes on Qlib-compatible expressions. [AlphaBench](https://github.com/CityU-MLO/AlphaBench)
- AlphaGen grammar: typed tree of feature, constant and time-delta nodes; pools serialized as expressions plus weights.
- Alpha101 operator vocabulary (rank, delay, delta, correlation, scale, decay, industry neutralization, time-series min, max, rank). [paper](https://arxiv.org/abs/1601.00991)
- WorldQuant BRAIN settings and submission gates (Sharpe, fitness, turnover band, sub-universe, self-correlation under 0.7, weight cap) are community-sourced, not official, but form the closest existing "artifact plus required evaluation configuration" convention. [community notes](https://github.com/alexisdpc/WorldQuant-alpha-trading)
- RD-Agent factor task record: name, description, formulation, variables, resources; a fixed input file and a fixed output file; hypothesis and feedback as JSON.
- Evaluator return contracts: a dictionary of scalars (AlphaEvolve); metrics plus artifacts such as error output fed into the next prompt (OpenEvolve); **public and private metrics plus text feedback (ShinkaEvolve)**, which maps directly onto a released-versus-sealed split.
- Richer semantics: the five-field schema plan (event, context, qualities, direction, output); the AEAP/SEADS gate record (coverage, Rank IC t-statistic, novelty correlation, partial IC, cross-sectional regression t-statistic, lookahead firewall result) [paper](https://arxiv.org/abs/2609.00731); FactorBench's admission rule of at least one hundred dates of defined IC per segment and a vendoring record of deviations. [FactorBench](https://github.com/ZhuoHan1998/FactorBench-Release)

### Quality-diversity specifics

- Niche definitions and archive sizes: OpenEvolve's MAP-Elites with ten bins over complexity and edit-distance diversity plus any evaluator feature; archive 100; five islands with ring migration of the top ten percent every fifty generations. ShinkaEvolve uses islands and an archive of forty without MAP-Elites, with novelty rejection at cosine 0.99. CodeEvolve reports MAP-Elites per island plus ring migration and inspiration-based crossover as needed to match AlphaEvolve on some problems (ablation detail **UNVERIFIED**). [CodeEvolve](https://arxiv.org/abs/2510.14150)
- Budgets: OpenEvolve defaults to one child per iteration and about a hundred iterations at cents to under a dollar per iteration depending on model; ShinkaEvolve caps a large run at twenty dollars and two hundred generations and reached state of the art on a packing problem in under 150 evaluations; FactorBench runs of alpha miners took five to twenty-eight hours per run on a mid-size open model; a separate benchmark reports two to four dollars per five-loop run on a frontier model. [alphamining-benchmark](https://github.com/EricZhang12138/alphamining-benchmark)
- Budget-matching caveats: proposal cost varies widely, so equal-proposal comparisons can grant nearly twice the compute; **token-matched, evolution beats independent sampling by at most about five percent on most task-method pairs** (October 2026) [paper](https://arxiv.org/abs/2610.23977); an incomplete validity check let a run post a huge score by scheduling only a handful of jobs (September 2026) [paper](https://arxiv.org/abs/2609.19799); **LLM mutation chains without selection collapse to templates while classical subtree mutation does not** (GECCO 2026) [paper](https://arxiv.org/abs/2606.05408).

### Does LLM evolution add value? Critiques

- No matched-compute comparison of LLM evolution against classical genetic programming for alphas exists; self-reported wins dominate.
- FactorBench (October 2026; nine miners, five markets, thousands of factors, ten basis points costs): no paradigm consistently dominates; in-sample advantages vanish out of sample; after neutralizing common styles only one method's long-short book stayed profitable; LLM agents decay less mainly because they fit less in-sample; all execution failures came from LLM pipelines; "pushing up a training-IC proxy is not evidence of alpha". [paper](https://arxiv.org/abs/2610.06947) (table values seen through a machine-generated summary; verify)
- AlphaEval (August 2025): LLM miners score best on predictive power and financial logic and worst on perturbation robustness. [paper](https://arxiv.org/abs/2508.13174)
- AEAP/SEADS (September 2026): re-running discovery point-in-time, out-of-sample Sharpe of LLM miners sits modestly above a no-discovery floor, gross of costs; combining admitted factors lowered out-of-sample Sharpe in fourteen of fifteen replicates; LLM backbone leakage is "soft, not absent". [paper](https://arxiv.org/abs/2609.00731)
- EverMine (September 2026): self-evolving research capabilities gave no consistent gain; gains came from parameter tuning of existing structures. [paper](https://arxiv.org/abs/2609.33524)
- Memorization and lookahead: alpha shrinks after the model's knowledge cutoff and forecasting ability is not identified under memorization. [Look-Ahead-Bench](https://arxiv.org/abs/2601.13770v1) · [paper](https://arxiv.org/abs/2605.23959) · [note](https://www.vbase.com/blog/llm-alpha-look-ahead-bias/)
- AlphaSchema's finding that implementation quality barely depends on which model implements a plan implies the loop and the evaluator, not the model, carry the value. [paper](https://arxiv.org/abs/2607.26642)

Artifact fields (`mechanism_card`, `formulation`, `variables`, `complexity`) in plan 4.3; the mixed operator set, weighted parent rule, mechanism-diversity requirement, novelty gates, veto memory and budget units in plan 6.4; the incremental-contribution metrics and fold-majority rule in plan 7.5–7.6; the matched-budget control arm in plan Phase 7; the structural lookahead firewall in plan 7.3.

## B.3 Evaluation statistics, feedback governance and point-in-time data

### Multiple testing and backtest overfitting

- **Deflated Sharpe ratio** (Bailey and López de Prado, 2014): evaluate the probabilistic Sharpe ratio against the expected maximum Sharpe of N zero-skill trials; the expected maximum grows with trial count and trial variance. Implementations differ on raw versus excess kurtosis; correlated trials need an effective N from clustering the trial correlation matrix. **False Strategy Theorem** (2021): no fixed threshold rejects false strategies without a trial count, so the evaluator must own the trial ledger. [DSR paper](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf) · [theorem](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=3221798) · [implementation notes](https://whatworksintrading.substack.com/p/deflated-sharpe-ratio-when-your-strategy)
- **Probability of backtest overfitting via combinatorially symmetric cross-validation** (Bailey, Borwein, López de Prado and Zhu, 2016): build the period-by-trial performance matrix, split into S blocks, enumerate all half-and-half in-sample and out-of-sample assignments, record the out-of-sample relative rank of each in-sample winner; PBO is the share with logit at or below zero. Only as honest as the matrix: omitting failed trials biases it down. [paper](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2326253) · [R package notes](https://cran.r-project.org/web/packages/pbo/readme/README.html)
- **Harvey, Liu and Zhu** (2016): recommend a t-statistic above three for new factors; family-wise and false-discovery-rate hurdles that rise over time. Related: haircut Sharpe ratios and profit hurdles (Harvey and Liu 2015), double-bootstrap hurdles for a chosen false-discovery rate (2020), and the Hou-Xue-Zhang replication finding that most anomalies fail multiple-testing hurdles. Exact table values **UNVERIFIED**. [HLZ](https://academic.oup.com/rfs/article/29/1/5/1843824) · [Backtesting](https://people.duke.edu/~charvey/Research/Published_Papers/P120_Backtesting.PDF) · [2020](https://onlinelibrary.wiley.com/doi/abs/10.1111/jofi.12951) · [HXZ](https://ideas.repec.org/a/oup/rfinst/v33y2020i5p2019-2133..html) · [critique](https://arxiv.org/pdf/2206.15365)
- **Bootstrap reality checks:** White's Reality Check, Hansen's superior predictive ability test, Romano-Wolf stepdown and stepwise variants; the `arch` library implements these with stationary and circular block bootstraps. [stepwise SPA](https://ideas.repec.org/a/eee/empfin/v17y2010i3p471-484.html) · [arch](https://github.com/bashtage/arch)
- **Agent-specific results, 2025–2026:** a planted lookahead oracle with an absurd Sharpe **passed** deflated-Sharpe and PBO tests, so leakage safety must be structural (August 2026) [paper](https://arxiv.org/abs/2608.27734); research agents reward-hacked spontaneously in about thirty percent of open-ended pipeline tasks, review panels missed some, and **detailed feedback roughly doubled evasion** (September 2026) [paper](https://arxiv.org/abs/2609.28614); a survey found that very few agent-trading studies report time-consistent splits or an explicit cost model and recommends reporting search budget plus classical multiple-testing statistics (2026) [survey](https://arxiv.org/abs/2605.19337); a design note on a "holdout firewall" (immutable artifacts, predeclared bounded queries, Thresholdout- or Ladder-permitted answers only, append-only ledger, never per-date outputs) [issue](https://github.com/microprediction/metareasoning/issues/50).

### Small-universe evaluation (N = 31)

- Metrics: per-period Spearman Rank IC and its mean, IC information ratio, t-statistic equals ICIR times the square root of the period count (Newey-West standard errors when horizons overlap), IC decay across horizons, rank autocorrelation for turnover. IC volatility is strategy risk the risk model misses (Qian and Hua 2004). The fundamental law gives IR as IC times the square root of breadth, with breadth reduced by correlation among the 31 indices; turnover costs always lower the ratio. [IC diagnostics](https://quanterlab.com/articles/diagnostics-information-coefficient) · [Qian-Hua](https://joim.com/active-risk-information-ratio) · [breadth](https://www.robeco.com/en-int/insights/2018/04/fundamental-law-of-active-management-shows-way-to-higher-information-ratio) · [Ding-Martin](https://www.sciencedirect.com/science/article/pii/S0927539817300543) · [turnover-adjusted IR](https://arxiv.org/abs/2105.10306v1)
- **Noise levels under no skill:** Spearman correlation has variance 1/(n−1), so one period's Rank IC has standard deviation about 0.183 at n = 31; the top-7 hit count is hypergeometric with mean 7/31 and one period's hit rate has standard deviation about 0.141. [Spearman variance](https://encyclopediaofmath.org/wiki/Spearman_coefficient_of_rank_correlation) · [hypergeometric variance](https://platform.commit.tu-berlin.de/en/book/fsp/chapter/ch04/section/s02)
- **Detectability (derived by the research pass from those nulls, assuming independent periods):** with about 354 weekly, 82 monthly and 27 quarterly periods from January 2020 to October 2026, the smallest detectable mean Rank IC at t = 2 (t = 3) is roughly 0.019 (0.029) weekly, 0.040 (0.060) monthly, 0.070 (0.105) quarterly; hit rates must exceed about 24.1% (24.8%), 25.7% (27.3%) and 28.0% (30.7%). In ICIR terms, 0.2 needs 100 periods for t = 2 and 225 for t = 3. Quarterly signals are essentially undetectable at conventional hurdles with this history. Weekly counts are inflated by overlapping horizons; use HAC errors or block methods.
- **Uncertainty:** stationary bootstrap (Politis and Romano 1994) or circular block bootstrap with automatic block length (Politis and White 2004 with the 2009 correction, implemented in `arch`); studentized time-series bootstrap for Sharpe differences (Ledoit and Wolf 2008). Placebos: circular time-shift of the signal preserves autocorrelation but has only T−1 distinct shifts, so p-value resolution is 1/T and zero must never be reported; add within-date cross-sectional permutation. [PPW 2009](https://public.econ.duke.edu/~ap172/Patton_Politis_White_2009.pdf) · [Ledoit-Wolf](https://www.econ.uzh.ch/apps/workingpapers/wp/iewwp320.pdf) · [permutation notes](https://www.susanpotter.net/quant/monte-carlo-permutation-tests-strategy-significance/)

### Feedback-release governance

- **Ladder** (Blum and Hardt, 2015): release a new rounded score only if it beats the submitter's best by at least a step, otherwise re-release the best; leaderboard error depends only logarithmically on the number of submissions; a parameter-free variant exists. The **Shaky Ladder** (2017) adds noise and exposes an attack on the deterministic version at small sample sizes, warning that its constants may not be good practical choices. [Ladder](https://proceedings.mlr.press/v37/blum15.pdf) · [Shaky Ladder](https://arxiv.org/abs/1706.02733)
- **Thresholdout** (Dwork et al., 2015): answer each query with the training estimate unless it differs from the holdout by more than a noisy threshold, then return a noised holdout value and spend budget; the authors' demonstration code uses constants weaker than the proofs require. [paper](https://arxiv.org/pdf/1506.02629) · [demo code](https://github.com/andyljones/thresholdout/blob/master/thresholdout.py)
- **Kaggle evidence:** across more than a hundred competitions, little adaptive overfitting, with exceptions for non-IID splits, two-stage contests and small test sets (2019). [paper](https://proceedings.neurips.cc/paper/2019/file/ee39e503b6bedf0c98c388b7e8589aca-Paper.pdf)
- **Allouah and Duchi (September 2026):** multi-criteria feedback makes worst-case holdout size exponential in the number of criteria; following the public ranking after 128 submissions cut held-out score by one to five percentage points; **one released score cost about 1.4 points, eighteen scores about 4.3**; coarser feedback delays harm but does not remove it. [paper](https://arxiv.org/abs/2609.32109) · [code](https://github.com/ysfalh/false-benchmark-progress)
- **Rules adopted in plan 7.7:** one scalar per artifact plus coarse flags; Ladder on the validation window with step equal to one block-bootstrap standard error; hard query budget per lineage and generation; every evaluated candidate logged and counted; a sealed confirmation window queried at most once per protocol version and then extended only by forward tracking.

### Point-in-time handling

- **China disclosure deadlines** (CSRC regulations): annual reports within four months of fiscal year end, interim reports within two months of June 30, quarterly reports within one month of quarter end; the first-quarter report may not precede the annual report. A 45-day lag is not safe for interim reports; 90 days is conservative. Prefer as-of joins on actual announcement dates; where only approximate dates exist use the deadline as the floor and run an extra-lag sensitivity. [CSRC](https://www.csrc.gov.cn/csrc_en/c102030/c1371072/content.shtml)
- Academic conventions: four-month availability lag with one-month characteristic lag (Jensen, Kelly and Pedersen); six-month annual and four-month quarterly lags (Chen and Zimmermann). Vendor point-in-time databases keep preliminary and final values with point dates. [JKP documentation](https://jkpfactors.s3.amazonaws.com/documents/Documentation.pdf) · [Chen-Zimmermann](https://arxiv.org/pdf/2212.10317) · [Compustat Snapshot](https://kenanflaglerresearchtools.web.unc.edu/research-resource/compustat-snapshot/)
- **Shenwan classification vintages:** the 2021 scheme (released June 23, 2021) raised level-1 industries from 28 to 31, with new indices launched December 13, 2021; studies use 31-index data back to 2010 or 2014, implying back-calculated history. Whether pre-December-2021 history is backfilled under the 2021 scheme is **UNVERIFIED**; label it reconstructed. [classification](https://baike.baidu.com/en/item/Shenwan%20Industry%20Classification/1476261) · [launch report](https://cs.com.cn/qs/202112/t20211222_6229719.html)
- **Honest labelling:** lookahead freedom formalized as temporal non-interference, undecidable in general and checkable in linear time for a fragment covering windowing, resampling, joins and vintage reads; empirical detectors certify nothing by their silence (July 2026). ### Blackboard store

- Postgres over SQLite for a security reason, not scale: SQLite has no per-role privileges, so any process holding the file can write any table and the research-versus-evaluator boundary cannot be enforced in the database; Postgres offers grants per schema and table, row-level security (owners and superusers bypass unless forced) and peer authentication. [row-level security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) · [peer auth](https://www.postgresql.org/docs/current/auth-peer.html)
- LISTEN/NOTIFY takes a global lock at commit and has hurt under heavy concurrent writes; fine at this scale as a wake-up signal with skip-locked polling doing the work. [incident](https://recall.ai/blog/postgres-listen-notify-does-not-scale) · [scalability note](https://dbos.dev/blog/postgres-listen-notify-scalability)
