## What maximum effort changed, and what it did not establish

The prior low-effort adaptive run used 8377 output tokens, 294021 total tokens,
209.46 seconds and 2.519708 CNY exposure. The completed max/32768 adaptive run used
63188 output tokens, 479799 total tokens, 826.23 seconds and 5.102152 CNY. It did
more inference, while still retaining the baseline and missing a prose defect.
The response-cap/authority differences and single-case sample prevent attributing
these outcomes solely to effort or claiming either setting is generally better.
Provider completion tokens include reasoning and answer/tool output; they are not
a separate measurement of useful reasoning.

The evidence does not support the earlier categorical conclusion that no factor
can be optimized. It shows a coherent starting factor, very limited close-only
data, a supervisor that reinforced the initial analyst's conservative conclusion,
and a control that explored but deferred a normalization hypothesis. Exploration,
adoption and proof of investment benefit need separate criteria. Maximum effort
alone did not resolve this distinction or make model-only prose review reliable.

## Export, UI and environment findings

The initial adaptive export stopped at its native-completion assertion. Large tool
results had been truncated near 50 KB, dropping the completion objects from the
model-visible JSON. The native compressed session event log independently records
all three tasks' completed transitions. A frozen native-log/Decimal check passed
before the fixed arm was launched; the runtime and research instructions remained
identical. The exporter now checks native event identity, ordering, latest task
revisions and owners, cross-checks available wire receipts, and retains the raw
log hash. It never invents a completion when the native task remains in progress.

The export repair exposed two format details in offline retries: DSH appends separate
Zstandard frames, and its tool view adds derived `ready`/`writeScopeWarnings` fields.
The parser now reads every frame under a size bound and compares the persisted
task fields. Regressions cover both, changed identities/history, conflicting receipts,
missing completion and reopened tasks. The failed exports and their partial files
are retained. Zstandard is now an explicit pinned dependency, already present in
the environment; the offline lock refresh first lacked cached metadata, then a
registry-only refresh succeeded. No such operation called a model/data provider.
After these reporting-only changes, **249 offline tests**, format/lint, JS parsing
and MIT checks pass. Both live arms still reference the same earlier source freeze.

Desktop 1440×1000 render and reload checks passed with no console errors; 390×844
screenshots retain the mobile clipping limitation. A separate UI attribution issue
is now recorded: native DSH displayed Codex's concurrent repository edits as
session file-change cards because the research workspace sits inside the same
Git tree. The GLM tools did not edit those files. UI root-token counters also cover
the supervisor only; the audited ledger totals above include all children. These
cards/counters must not be used as the agent-work record.

Across the live stages, the shared guard/DSH/data process tree peaked at **619.2 MiB
RSS** and **0.1281 sampled CPU cores**, with no swap. Mean usage was 0.0345–0.0432
cores in the 32768-token pair; minimum host available RAM was 10.21 GiB and minimum

recommendation. CPU intervals can miss short-lived children; host readings include
