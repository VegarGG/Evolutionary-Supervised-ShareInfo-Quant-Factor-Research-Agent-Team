comparison, warm-up arithmetic and usage-reporting errors, followed by one fresh

## Diagnosis and changes under test

The evidence does not isolate a model-intelligence ceiling. GLM produced a false
analyst equation, underspecified comparison wording and an outdated usage claim.
The harness had concrete control gaps: findings bypassed the count-equation
validator; the comparison grammar recognized only one phrasing; final chat was
allowed to quote a snapshot taken before the finalization request. A larger model
could improve error rates, but it would not make those interfaces reliable.

`typed-v1` validates findings before acceptance and makes them reference current
host facts instead of repeating numbers. Required closes per signal and actual
warm-up exclusions remain separate facts. Inspections compute two named measures
(max-minus-min and max/min of per-symbol sample score SDs) against the exact
assigned candidate, with either paired eligible symbol/date keys or each spec's
own eligible cohort. Revision references bind the inspected specification and
named measure/cohort; the host renders values and limitations. Qualitative
motivation remains model-authored and requires independent review. Grammar
checks are counterexample defenses, not a proof of arbitrary prose.

Finalization uses DSH's native `ToolExecution.concludeTurn()` after the final
model request settles. A host receipt reports every team work request and worker
acknowledgement, tokens and conservative exposure. There is no extra paid
supervisor acknowledgement or model-generated accounting summary. The native
footer remains session-only; the explicit team receipt is authoritative.

Synthetic integration additionally exposed a numerical definition mismatch:
bitwise float inequality and independent Decimal recomputation disagreed on tiny
score differences. New typed packages count changed scores using relative
tolerance 1e-10 and absolute tolerance 1e-12; eligibility differences always
count. This matches the independent audit's existing numerical accuracy criterion.
Legacy packages retain their original definition and immutable results.

## Live harness failure and bounded repair

The initial fixed attempt stops incomplete after 13 settled GLM calls, 388311
tokens and 4.074348 CNY conservative exposure. Four comparison rejections and
one decision-length rejection consume the designer's six work requests. The
harness incorrectly combines “window equal to the lookback” with “dispersion
evidence” in another clause as a measured equality. It also flags the legitimate
caveat that measures do not establish improved comparability. The original
error does not identify the offending field or text. These are reproduced
harness defects, not evidence of a model-intelligence ceiling.

The repair splits clauses, recognizes explicit non-establishment caveats and
returns the exact offending field and clause. Nine additional counterexamples
bring the offline suite to 318 passing tests. The original failed package and
its immutable source snapshot remain; its adaptive counterpart never starts.
A recorded replacement pair uses `typed-repair-fixed-03` and
`typed-repair-adaptive-04`, with identical repaired sources and the original
prompt/data. The original 443-request, 10000-credit and 100 CNY local ceilings
are unchanged. The failed attempt consumes the allowance; it is not erased or
reset. No additional automatic pair follows this repair.

The failed analyst also overgeneralizes that normalization necessarily requires
additional trailing history. The inspected matching window does not. This
model-prose mistake is retained separately from correct host counts, the
comparison-guard failure and the absence of a finalized artifact. Typed numeric
facts do not prove all surrounding qualitative claims.

three analyst findings, one new normalization inspection, a substantive revision
and exact-version review. There are no rejected submissions. Its designer adopts
normalization and explicitly corrects the analyst/supervisor premise that the
matching volatility window would lose warmup rows. All 171 non-null scores change;
eligibility remains 57 per symbol. Named comparisons and host arithmetic pass.
The final 10965-byte native receipt reports eight supervisor work requests, no
supervisor acknowledgement and all 18 team calls, matching the ledger exactly.

Independent review flags the hypothesis wording “now divided by the trailing
daily-return standard deviation”: it omits the denominator's `sqrt(lookback)`
term. The executable formula, host definition and cited source include that term.
For the chosen lookback, the prose formula would produce scores `sqrt(5)` times
the computed scores. The model reviewer marks all checks consistent and no issues;
the supervisor calls the report clean. Preserve that false semantic pass. This
is a model-definition error and a remaining validation gap, not a host arithmetic
or usage-accounting failure.

A narrow post-run regression now rejects this explicit incomplete definition and
points to the host spec reference; complete definitions, negations and qualitative
motivation remain allowed. Five added tests bring final offline verification to
323 passing tests. This guard was added **after** both completed live snapshots;
it has not received another paid validation. Legacy outputs are unchanged. This
bounded grammar does not establish general semantic correctness.

## Checkpoint decision

The three requested contracts are implemented and exercised live: comparison
measures/cohorts, host count references and post-settlement team reporting. The
remaining explicit-definition mismatch keeps the clean-pair/core gate provisional.
The observed errors establish neither a model-intelligence ceiling nor a purely
harness-only problem. The first patch's false-positive grammar and inadequate
local-budget headroom were engineering/operator defects; repeated warmup and
formula prose mistakes, including a false peer approval, are model errors that
the harness must contain. A bigger model is not a substitute for precise contracts.

Next keep executable definitions exclusively in host-rendered fields or require
explicit prose definitions to bind their complete operands; verify the new
counterexample guard and supervisor assignment/schema consistency. Then rerun a
bounded descriptive acceptance case before attaching parent-child evolution and
released-report matching. Broader unseen cases, operational recovery, role/context
integration, evaluation/release gates, deployment/load/security and owner/mobile UX
remain production work. No official acceptance or production readiness is claimed.
