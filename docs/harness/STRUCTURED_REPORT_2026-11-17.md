This work package implements the owner's request to fix final-output reporting and
rerun the fixed/adaptive BaoStock case with **GLM 5.3 at maximum effort**. The host
now renders computed facts, units, timing limits and provenance from a typed report;
the model supplies separately identified hypotheses and decisions. The first fixed
arm completed, but its adaptive counterpart failed while copying a candidate hash.
Both attempts are preserved. A recorded interface repair binds immutable task
references on the host and a fresh pair verifies that repair. These are development
research artifacts, without evaluation, pool changes or official acceptance.

## Reporting contract

`structured-v3` preserves legacy and bounded-v2 records. The initial interface used
exact inspection and fact hashes; the repaired `task_bound` mode resolves the
declared task/inspection handles to those same immutable references. The host supplies the chosen spec,
counts, metrics, units and evidence limits; the model cannot replace them with copied
numbers. Qualitative hypotheses and reasons refer to fact IDs and remain explicitly
model interpretations. Literal source quotes are retained separately.

The exact report binds the candidate, data/spec/score hashes, source hashes, full
model proposal and calculation provenance. Reviews use typed consistency decisions
and the complete report hash. A clean review cannot target a stale or partial
artifact. Failed reviews still permit bounded adaptive repair and exact new review.
Hash equality proves identity, not that an interpretation is true.

The report distinguishes:

- Raw return and volatility-normalized return: both dimensionless. Scaling changes
  magnitude, not units; a raw return is already invariant to constant price rescaling.
- Eligible signals and available next observed closes: neither demonstrates
  tradability, fills or costs. Future evaluation labels begin after the execution
  close, never the signal-to-next-close interval.
- Required window length and warmup exclusions, with counts calculated from rows.
- Deterministic host calculation requested by an attributed worker and someone
  merely reading that worker's receipt.
- Inspected development data and an untouched holdout; this case is development-only.
- Native task completion, model review, independent audit and official acceptance.
- A session-only native usage footer and post-drain team totals including worker
  and supervisor acknowledgements.

The native `finalize_case` tool renders host-generated text. In DSH, open
**Completed → Called tools → finalize_case**. Computed facts, limitations, provenance,
model hypotheses, finding dispositions and source excerpts are separate. Final chat
is instructed to contain the candidate ID and pending-independent-audit status.
That is a prompt, not a validator of every chat word: the adaptive root also supplies
a short stage summary. Intermediate chat and additional model summaries are not
the independently audited report.

The numeric-copy restriction and known semantic counterexamples are deliberately
bounded controls. They do not prove arbitrary qualitative claims, source quality,
investment benefit or general research capability. Independent semantic review
remains necessary. Report discoverability, root-only usage summaries and complete
mobile workflow acceptance remain UX work.

The initial fixed analyst produced four findings, the designer adopted a volatility-
normalized candidate with lookback/window five and no return bound, and the reviewer
checked its exact report. That changes 171 score rows without changing eligibility.
Three submissions were rejected before correction: two design reference errors and
a review that put ordinary caveats in its defect list while selecting a clean verdict.
The model's “common per-name scale” phrase is interpreted as dispersion; both raw and
normalized returns are already dimensionless, and improved comparability remains an
unproven hypothesis. This is a descriptive pass with limits, not an investment result.

The first adaptive analyst never reached an accepted finding after its ID failures.
The supervisor stopped. Its native root turn completed successfully as a stop report;
the research attempt did **not** succeed. Its arithmetic audit covers only the frozen
input/baseline, not a worker calculation. A UI-rendering pass for that stop report
must not be counted as a research pass.

In the task-bound control, the analyst corrected two exact-quotation rejections:
it inserted an extra “a” into “a revision is better.” All task-reference bindings
worked. The designer actually inspected both specifications, then rejected the
normalization hypothesis and retained the raw baseline. This is a permitted research
decision, not a failure to optimize. The normalized inspection changes 171 rows;
the **adopted final candidate changes zero**. The native reviewer approved the exact
report and all three tasks completed. No accepted tool submission is substituted
for actual native task completion.

Independent review passes the control's computed counts, units, timing, hashes and
calculation provenance, but withholds a clean semantic pass. Its rationale says
cross-name dispersion stays “about as wide” without naming a measure. The max/min
sample-SD ratio changes from 1.530835 to 1.546372, while the absolute max-minus-min
range changes from 0.01483349 to 0.61495438. The first supports a **relative**-spread
description; the second does not support an unqualified absolute-width equality.
A reader should not have to select the definition that makes the prose true.
Clarifying that comparison does not require changing the factor.

The analyst also made two questionable intermediate inferences: matching dispersion
rankings do not establish that raw score magnitudes are “dominated” by volatility,
and few zero returns do not guarantee positive SD because constant nonzero returns
also have zero SD. These are retained in a separate intermediate semantic review.
The designer rejected that normalization finding and actual host inspection, not
the invalid implication, verifies denominator positivity on this sample.

The repaired adaptive supervisor generates assignments from the current sources
and finding handles. Its analyst submits four cited findings in one successful
submission. The designer inspects both specs, then adopts normalization with the
same lookback/direction and no return bound. One overlong rationale is rejected and
shortened inside the unchanged 1600-character limit. The reviewer checks the complete
current report; all three native tasks and all terminal acknowledgements complete.
Independent arithmetic verifies the 171 changed scores. The final report correctly
keeps both raw and normalized scores dimensionless and treats comparability as an
intended research interpretation, not demonstrated equal dispersion or investment
benefit. Descriptive review passes with limits.

The adaptive analyst's earlier heading nevertheless says units and scale are
heterogeneous across the universe. Its body identifies the correct units, and the
final adopted disposition describes dispersion heterogeneity, but the heading is
wrong: magnitudes vary; units do not differ between the names. The intermediate
audit preserves that error and the unmeasured signal/volatility interpretation.
Its corrected final report does not retroactively validate every earlier sentence.

The repaired adaptive run uses 36.0% fewer tokens than its fixed control. That
observation is confounded by quotation retries and different chosen outcomes;
this single sequential pair cannot establish adaptive superiority. The real
adaptive topology remains analyze/design/review, without an extra repair stage.
The repair-and-new-review loop is separately verified in synthetic native fixtures.

### Offline counterexample repair after the live source freeze

The new bounded guard rejects the recorded “spread/dispersion stays/remains as wide”
claim unless its sentence names a maximum/minimum ratio or difference. Removing
the comparison also allows the same candidate; no computational change is forced.
Three regression cases exercise the actual rationale, decision and a named-measure
control. A fourth rejects the false universe-units heading before a finding is
accepted and allows the corrected shared-units/varying-magnitudes statement.
The same unit-heading check also applies to final qualitative arguments. Naming a
comparison measure still does not prove its value or interpretation.

Both repaired arms had already frozen their identical runtime snapshots before
this change. Their historical outputs remain unchanged, and the fixed report is
still marked `needs_semantic_clarification`. This additional guard is tested offline,
not live-revalidated or presented as a general semantic verifier. It supplements
the earlier unit/count/tradability repairs; it cannot establish production readiness.

Final audit review adds explicit independent specification-digest and changed-row
checks for each saved inspection and final report. Two regressions simulate a report
builder whose wrong field is consistently hashed; hash identity alone cannot catch
that error. All four unchanged real attempts pass the supplementary arithmetic
audit. The first supplementary output mistakenly reused the future-perturbation
row variable in a count field; that wrong-typed output is preserved as attempt 01,
then corrected and covered by a regression assertion. No model call or budget
mutation accompanies these read-only audits; original exports remain immutable.
