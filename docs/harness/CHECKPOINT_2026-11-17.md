## Engineering and acceptance plan

- Bound model-visible board replies to 24000 UTF-8 JSON bytes. Large immutable
  sources and events are accessible by hash-pinned 2500-character pages. Keep native
  task receipts outside the full board; retain full private artifacts and logs.
- Give each actor one separate acknowledgement request in the same aggregate
  ledger. Worker work is capped at six calls, supervisor work at twelve, each arm
  at 36 total requests and six native tasks. Reserve acknowledgement slots inside
  the atomic cash admission transaction. Native errors remain errors after submission.
- Expose closed attempts without a suggested next fixed stage. Check structured
  source-derived counts and the recorded false prose patterns; disclose the grammar's
  limits. A clean model review cannot override a recognized count defect.
- Distinguish motivated hypotheses, exploratory candidate adoption and investment
  benefit. Hypothesis citations establish provenance, not profitable alpha. Preserve
  retention/defer/reject decisions. Never force a factor change.
- Put DSH's research workspace inside its own empty Git boundary, so unrelated
  development edits cannot appear as native research work.
- Pass offline regression and scripted native UI tests before live model dispatch.
  Then run one fixed/adaptive pair with identical frozen sources, code, settings and
  per-arm bounds. The fixed sequence is analyze/design/review. Adaptive follow-ups
  must reference observed findings/reviews. Record all attempted tasks and failures.
