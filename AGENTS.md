# AGENTS.md: rules for every coding session

Project: Hybrid v1 Quantitative Factor Research (QFR).
Read `docs/PLAN_ALIGNMENT.md`, then `docs/HYBRID_V1_DEVELOPMENT_PLAN.md` and applicable
`docs/LOCAL_IMPLEMENTATION_REFERENCE.md` details. The owner's current instructions win.
Decision log: `docs/decisions.md`. These fifteen reconciled rules apply to every session.

1. Preserve Hybrid v1 scope and ordered stage gates. Do not implement a later stage before its prerequisites are accepted. Resolve routine ambiguity conservatively and log it; ask the owner before a material scope or goal change.
2. Enforce imports with import-linter: research and evaluation never import each other; registry imports neither; core imports no other QFR package; MCP imports core only and calls authorized APIs over HTTP. Private official-record and trial-ledger schemas live only in qfr_eval.
3. Research and MCP hold no evaluation credentials, administrative endpoint or signing key, cannot connect to eval_db, and cannot invoke, configure, prioritize or cancel evaluation or simulated accounts. Preserve three databases and least-privilege roles; assert grants with live tests.
4. Published artifacts are immutable. Every artifact write goes through the Registry API; never write its storage directly. Revisions create versions, with content hashes separate from implementation fingerprints. Database grants and triggers protect insert-only tables.
5. Evaluation pulls artifacts on its own schedule. There is no research push, notification trigger, queue-drain or evaluation-control tool. Starting idle containers creates no research, ingest campaign or spend.
6. Feedback is GET-only and released-only. Every official record and released report pins artifact id, content hash, protocol version, dataset snapshot and evaluator code. W3 measurements and private windows stay private. Released diagnostics are fixed enums, never execution-produced text; prior lineage bests retain their origin version.
7. Count every evaluated version and failed/withheld/diagnostic attempt in the private ledger. Write official records and ledger entries atomically when that behavior is implemented. Every write records principal, UTC timestamp and request id in an append-only event log.
8. Official measurement has no LLM, online inference, uncontrolled network access or wall-clock dependence. Use fixed configured seeds. Preserve reproducibility within the pinned runtime; predeclare cross-architecture numerical tolerances and exact structural checks. Builds, mocks and schema checks are not runtime or financial acceptance. Deployment targets are macOS on Apple Silicon first (Mac Studio with its existing Docker Desktop), then Linux AMD64; record host and container platforms separately and apply the target-specific acceptance order in PLAN_ALIGNMENT section H.
9. Research reads only authorized research-zone snapshots. Full data and epochs mount only into evaluation. Preserve separate timing, vintage and membership labels, nulls and prior exposure. Chinese text remains unchanged data. Never commit licensed inputs, credentials, secrets or private exports.
10. Contracts are Pydantic v2 first: regenerate JSON Schema and valid/invalid examples before dependent code. Use canonical sorted JSON for hashes. The Stage 0 initialization SQL is the baseline; subsequent database schema changes use reviewed Alembic migrations, one environment per database.
11. LLM access belongs only to research workers, and only when the authorized stage implements it. Calls require budgets and locally validated structured output. Use configured OpenAI-compatible online endpoints, with Kimi/GLM/DeepSeek production conformance still required. Secrets are references; unknown model IDs, endpoints, capabilities, prices and usage remain unknown. Never add a Claude/Anthropic SDK, local LLM runtime or silent unapproved fallback.
12. DSL operators look backward only and ship with causality property tests. Unsupported executable formats fail explicitly; no untrusted package executes without the approved no-network, non-root, read-only, resource-limited sandbox. Missing isolation is a readiness failure.
13. Jobs are durable and on demand. Default wall-clock and generation limits are unset. Pause, exhausted budget, missing input, data wait or a closed generation is not completion. Only an independent passing delivery receipt permits completion; investment promotion separately needs forward evidence and human approval.
14. Every tunable belongs in versioned configs; keep pilot and stock defaults distinct. Never change golden values, loosen tolerances or weaken tests to pass. Golden changes require original evidence and a decision. Tests make no real LLM calls; use offline fixtures. Preserve accepted P1 and all original source packages.
15. A work package ends with green `just check` and `just test`, updated code/tests/docs, and explicit limits on what was verified. Finish with the requested stage acceptance report and commit; do not merge without authorization.
